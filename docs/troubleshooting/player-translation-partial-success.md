# 선수 이름 번역 작업의 부분 성공 처리

## 1. 배경

VEYRO에서는 OpenAI를 활용하여 선수의 영문 이름을 한국어로 번역한다.

- 한 번에 최대 300명의 번역 대상을 조회한다.
- OpenAI에는 50명 단위로 번역을 요청한다.
- 번역 결과를 검증한 뒤 `Player` 엔티티의 `playerNameKo`에 반영한다.

## 2. 기존 문제 (Problem)

현재 `PlayerNameTranslationOrchestrationService.validateResult()`는 모든 번역 결과가 정상이어야 한다는 정책을 사용한다.

50명 중 단 1명의 번역 결과가 잘못되어도 해당 배치 전체가 실패한다.

예시:

- 요청한 선수: 50명
- 정상 번역 결과: 49명
- 잘못된 번역 결과: 1명
- 최종 결과: 50명 모두 저장되지 않음

이로 인해 성공적으로 한국어 이름을 할당할 수 있는 선수임에도 불구하고, 잘못된 번역 결과 1건때문에 나머지 정상적인 49건은 한국어이름 할당이 취소되고, 다시 외부 API 를 호출해야 하는 상황이 발생한다.

## 3. 원인 (Cause)

기존 로직에서의 중요한 검증은&#x20;

- 번역결과의 한국어 이름이 정상적인지 ( null / not blank )
- 번역 결과에서 중복된 선수는 없는지
- 요청대상 Id 와 결과대상의 Id 가 일치하는지. + 누락된 플레이어는 없는지
- 결과대상이 DB 에 존재하는지&#x20;

## 4. 개선 방향 (Decision)

1명마다 트랜잭션 적용 vs 실패자에 대해서 로그를남기고 어드민이 직접 처리 ( 번역 )

---

1명마다 트랜잭션 적용 

장점 : 

- 문제가 생겼을때, 특정 실패자 때문에 다른 성공자에 대해서 신경을 쓰지 않아도됨. ( 특정 플레이어가 실패했다고해서 모두가 영향을 받지않음. )

단점 : 

- 데이터베이스 커넥션을 얻으려고하는 횟수가 굉장히 증가함. ( 선수 1명당 커넥션을 얻으려고하니 ... ) -> 사용자가 적을때는 크게 문제가 되지않겠지만, 사용자가 많아지게되면 번역작업때문에 사용자는 원하는 응답을 늦게 받을 수 있는 가능성이 존재함.

---

실패자에 대해서 로그를남기고, 해당 배치단위의 실패를 적용하고 문제대상의 대한 수동처리 

장점 : 

- 데이터케이스 커넥션을 얻으려고 하는 횟수가 굉장히 감소함. 배치에 대해서 1번만 얻으면 끝. 

단점 : 

- 특정 문제 플레이어때문에 정상적인 플레이어도 번역작업에 실패 -> 외부 API 호출 비용 증가 가능.  

---

배치단위로 남기되, 로그를 작성해서 어떤 플레이어가 어떤 이유때문에 실패했는지 확인.

-> 해당 플레이어는 수동으로 처리 -> 이후, 다시 번역 API 를 호출해서 진행하는식으로 결정.

( 이전에 성능테스트같은 부분을 했을때, 데이터베이스 커넥션을 얻는데에 굉장히 비용이 크다는것을 봤기때문에 )
